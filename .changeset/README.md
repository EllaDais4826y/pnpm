# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works
with multi-package repos, or single-package repos to help you version and publish your code. You can
find the full documentation for it [in our repository](https://github.com/changesets/changesets)

## Understanding this folder

We have a `config.json` in this folder that is used to configure the behavior of Changesets. You should
consider what options are available to you in the [config docs](https://github.com/changesets/changesets/blob/main/docs/config-file-options.md)

If you are unsure what these options mean, we recommend reading the [introductory walkthrough](https://github.com/changesets/changesets/blob/main/docs/intro-to-using-changesets.md)

## What do these markdown files do?

Each file in this directory (except `README.md` and `config.json`) is a changeset. A changeset is an
intent to release a set of packages at a particular semver bump type with a summary of the changes made.

A changeset that looks like this:

```md
---
"pkg-a": minor
"pkg-b": patch
---

A description of the changes
```

means that `pkg-a` should be bumped as a `minor` version bump, `pkg-b` should be bumped as a `patch`
version bump, and the description of the changes should be included in the changelogs of both packages.

## How do I add a new changeset?

Run `pnpm changeset` to interactively create a new changeset. This will walk you through the process
of selecting which packages to include in the changeset and what version bump type to use.

Alternatively, you can manually create a new markdown file in this folder following the format above.

## I see stale changesets in this folder

Changesets are consumed when a version bump is made. If you see stale changesets, it likely means
that a version bump has not been made yet. Run `pnpm changeset version` to consume all changesets
and bump the relevant packages.
